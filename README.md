
# Лабораторная работа 1: Разработка защищенного REST API с интеграцией в CI/CD

## Описание проекта
Данный проект представляет собой защищенное REST API для простого приложения "Доска сообщений" (Message Board). Пользователи могут регистрироваться, авторизовываться, публиковать текстовые сообщения и просматривать сообщения других пользователей. 

Проект упакован в Docker-контейнеры для удобного развертывания вместе с базой данных.

**Стек технологий:**
- Backend: Python, Flask
- База данных: PostgreSQL
- ORM: Flask-SQLAlchemy
- Аутентификация: JWT (PyJWT) + Argon2 (хэширование)
- Защита от XSS: Bleach
- Инфраструктура: Docker, Docker Compose

---

## Запуск проекта локально
Для запуска приложения и базы данных необходимо наличие установленного Docker и Docker Compose.
Выполните в корневой директории проекта команду:
```bash
docker-compose up --build
```
API будет доступно по адресу: `http://localhost:5000`

## Документация API (Эндпоинты)

### 1. `POST /auth/register` (Вспомогательный метод)
Регистрация нового пользователя.
* **Тело запроса (JSON):** `{"username": "user1", "password": "mypassword"}`
* **Пример вызова (cURL):**
  ```bash
  curl -X POST http://localhost:5000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"student", "password":"password123"}'
  ```

### 2. `POST /auth/login` 
Аутентификация пользователя и получение JWT-токена.
* **Тело запроса (JSON):** `{"username": "user1", "password": "mypassword"}`
* **Успешный ответ:** `{"token": "<jwt_token>"}`
* **Пример вызова (cURL):**
  ```bash
  curl -X POST http://localhost:5000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"student", "password":"password123"}'
  ```

### 3. `GET /api/data` (Защищенный эндпоинт)
Получение списка всех опубликованных сообщений.
* **Заголовки:** `Authorization: Bearer <ваш_токен>`
* **Пример вызова (cURL):**
  ```bash
  curl -X GET http://localhost:5000/api/data \
  -H "Authorization: Bearer ВАШ_ТОКЕН"
  ```

### 4. `POST /api/data` (Защищенный эндпоинт - Собственный метод)
Публикация нового сообщения текущим авторизованным пользователем.
* **Заголовки:** `Authorization: Bearer <ваш_токен>`
* **Тело запроса (JSON):** `{"content": "Текст вашего сообщения"}`
* **Пример вызова (cURL):**
  ```bash
  curl -X POST http://localhost:5000/api/data \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ВАШ_ТОКЕН" \
  -d '{"content":"Привет! Это мое первое сообщение."}'
  ```

## Реализованные меры защиты (OWASP Top 10)

### 1. Защита от SQL-инъекций (SQLi)
* **Как реализовано:** В проекте принципиально не используется конкатенация строк для формирования SQL-запросов. Взаимодействие с базой данных происходит исключительно через ORM-библиотеку `Flask-SQLAlchemy`.
* **Механизм:** ORM под капотом использует параметризованные запросы (Prepared Statements) драйвера `psycopg`. Это гарантирует, что любые пользовательские данные обрабатываются базой данных как значения, а не как исполняемый SQL-код.

### 2. Защита от межсайтового скриптинга (XSS)
* **Как реализовано:** Для защиты от XSS-атак применяется библиотека `bleach`. 
* **Механизм:** При публикации нового сообщения (`POST /api/data`) весь пользовательский ввод принудительно проходит через функцию санитизации `bleach.clean(data['content'])` *до* сохранения в базу данных. Эта функция вырезает потенциально опасные HTML-теги и JavaScript-код (например, `<script>alert('XSS')</script>`), оставляя только безопасный текст.

### 3. Защита от проблем аутентификации (Broken Authentication)
* **Хранение паролей:** Пароли пользователей **не хранятся в открытом виде**. При регистрации пароль хэшируется с использованием алгоритма `argon2`.
* **Сессии (JWT):** После успешной проверки логина и пароля сервер генерирует JSON Web Token (JWT), подписанный секретным ключом сервера (`SECRET_KEY`). Токен имеет ограниченный срок жизни (1 час).
* **Авторизация (Middleware):** Написан кастомный декоратор `@token_required`, который применяется ко всем защищенным эндпоинтам. Он проверяет наличие заголовка `Authorization`, валидность подписи токена и срок его действия. Без валидного токена доступ к API блокируется (возвращается код 401 Unauthorized).
